================================================================================
1. OVERVIEW
================================================================================

The CCI Department Guidance API provides programmatic access to:
- Department information and curricula
- Assessment questions and scoring
- Student assessment management
- Result calculation and recommendations
- Feedback collection
- Administrative analytics

Protocol: REST
Format: JSON
Status Codes: Standard HTTP

================================================================================
2. AUTHENTICATION
================================================================================

PUBLIC ENDPOINTS:
- No authentication required for:
  - Department information
  - Starting/completing assessments
  - Submitting feedback

ADMIN ENDPOINTS:
- Currently open (no auth)
- Future: JWT-based authentication planned

================================================================================
3. RESPONSE FORMAT
================================================================================

SUCCESS RESPONSE:
{
  "success": true,
  "data": { ... },
  "message": "Optional success message"
}

ERROR RESPONSE:
{
  "success": false,
  "error": "Error message",
  "details": { ... } // Optional error details
}

================================================================================
4. ERROR HANDLING
================================================================================

HTTP Status Codes:
200 - Success
201 - Created
400 - Bad Request (validation error)
401 - Unauthorized
403 - Forbidden
404 - Not Found
429 - Too Many Requests
500 - Internal Server Error

Common Errors:
- Missing required fields
- Invalid data format
- Resource not found
- Session token mismatch
- Rate limit exceeded

----------------------------
Description: Start new assessment session
Auth: None
Content-Type: application/json

Request Body:
{
  "student_id": "HU/IT/2024/001",     // Required
  "student_name": "John Doe",          // Required
  "student_email": "john@example.com"  // Required, must be valid email
}

Response (200):
{
  "success": true,
  "data": {
    "assessment_id": "uuid",
    "session_token": "token-string",
    "questions": [
      {
        "id": "uuid",
        "question_text": "What interests you most?",
        "text": "What interests you most?",
        "category": "interests",
        "question_order": 1,
        "options": [
          {
            "id": "uuid",
            "option_text": "Programming and coding",

5.4 FEEDBACK ENDPOINTS
--------------------------------------------------------------------------------

POST /api/feedback
------------------
Description: Submit user feedback
Auth: None
Content-Type: application/json

Request Body:
{
  "assessment_id": "uuid",              // Optional
  "rating": 5,                          // Required (1-5)
  "comment": "Great system!",           // Optional
  "helpful": true,                      // Optional
  "would_recommend": true,              // Optional
  "user_name": "John Doe",             // Optional
  "user_email": "john@example.com"     // Optional
}

Response (200):
{
  "success": true,
  "message": "Feedback submitted successfully",
  "data": {
    "id": "uuid"
  }
}

Validation Errors (400):
{
  "success": false,
  "error": "Validation failed",
  "details": {
    "fields": [
      {
        "field": "rating",
        "message": "Rating must be between 1 and 5"
      }
    ]
  }
}

GET /api/feedback
-----------------
Description: Get all feedback (admin only)
Auth: Admin (future)
Query Parameters:
  - page: Page number (default: 1)
  - limit: Items per page (default: 10)

Response (200):
{
  "success": true,
  "data": {
    "feedback": [ ... ],
    "pagination": {
      "page": 1,
      "limit": 10,
      "total": 100,
      "totalPages": 10
    }
  }
}

================================================================================
6. RATE LIMITING
================================================================================

Current Limits:
- 100 requests per 15 minutes per IP
- In development mode: No limits

Headers:
- RateLimit-Limit: Maximum requests
- RateLimit-Remaining: Requests remaining
- RateLimit-Reset: Reset timestamp

Rate Limit Exceeded (429):
{
  "success": false,
  "error": "Too many requests. Please try again later.",
  "retryAfter": 900
}
